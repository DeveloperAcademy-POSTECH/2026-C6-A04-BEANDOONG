# 스티밍 소리 모델 v3.5

## v3.5 업데이트 (2026-11-09)

2026-11-08 추가 데이터 재학습 후보(`ModelRefresh20261108R2/models/iteration3`)의 스티밍 분류 모델을 적용하고 자동 종료를 연결했습니다. 버전은 v3.5이며 Swift·리소스 이름에는 `V3_5`를 사용합니다. 기존 v3.0 모델 파일은 앱 번들에서 교체합니다. 분류 구조를 시간 특징 후보로 바꾸지 않고 현재의 게이트→공기주입/쇳소리 갈래를 유지합니다.

- 스티밍 분류: `ChicModelV3_5Gate`, `ChicModelV3_5Air`, `ChicModelV3_5Metallic`.
- 재학습 입력과 맞추기 위해 모든 갈래가 **고역 강조 없는 원음 특징 273개**를 공유합니다. 기존 11~12kHz +7dB 필터는 분류에 적용하지 않습니다.
- 공기주입 갈래는 `air`·`sputter`·`rolling` 삼분류입니다. 롤링 점수가 최댓값이면(동률 포함) 기존 `other` 표시 상태로 되돌립니다. 그 외에는 파바박 점수 0.5 이상이면 파바박, 공기주입 점수 0.5 초과이면 공기주입이며 두 기준 모두 미달하면 롤링(`other`)으로 판정합니다. 공기주입 점수가 정확히 0.5인 경우에는 공기주입으로 판정하지 않습니다. 쇳소리 갈래는 쇳소리가 최댓값이면서 0.65 이상이어야 합니다. 게이트의 숨소리·휘파람은 기타로 처리합니다.
- 표시는 현재 앱의 **10프레임 최다 집계, 공기주입 1묶음·롤링 2묶음·쇳소리/파바박 3묶음 연속**을 유지합니다. 초기 기타만으로는 피드백 화면으로 전환하지 않습니다.
- 종료 감지는 하나의 Core ML 리소스에서 기존 작업 점수와 재학습한 종료음·청소음 점수를 별도 출력으로 계산합니다. 기존 실험의 별도 공기주입/롤링 이력 분류기는 앱에 넣지 않습니다.

### air 2차 정상 롤링 추가 (2026-11-09)

`ChicModelV3_5Air.mlmodel`을 공기주입·파바박·정상 롤링 삼분류로 재학습했습니다. 게이트가 `air` 또는 `sputter`로 보냈더라도 2차의 `rolling` 점수가 가장 높으면 최종 원시 판정을 `other`로 반환합니다. 이미 롤링을 표시하고 있다면 계속 유지할 수 있고, 다른 상태에서 돌아올 때는 기존 10프레임 집계·롤링 2묶음 연속 조건을 적용합니다. 모델 수와 실행 횟수는 늘리지 않습니다.

최신 125개 출처에서 `normal_air`·`surface_sputter`·`balanced_rolling`만 사용했습니다. 일반 기타·종료음·청소음을 정상 롤링으로 합치지 않았습니다. 표본은 공기주입 10,122개, 파바박 2,758개, 롤링 4,866개이며 롤링 표본을 두 번 사용해 총 22,612행으로 학습했습니다. 추가 반례의 학습 전용 배치를 유지했습니다.

기존 출처 그룹 분리 5개 개발 분할에서 롤링 비중 1배·2배를 비교해 2배 후보를 적용했습니다. 게이트·쇳소리 모델과 표시 규칙은 고정했습니다. 롤링 비중 1배는 잘못 air 갈래로 들어온 1,120프레임 중 30개, 2배는 48개를 롤링으로 보정했습니다. 다만 **롤링 구간의 공기주입 오표시 묶음 수는 기존 138개에서 138개로 그대로**이며, 파바박 정답 표시 묶음은 16개에서 7개로 감소했습니다. 라벨 추가가 전반적인 오탐 해결이나 파바박 성능 향상을 뜻하지 않습니다.

아래 평가는 공기주입 점수 0.5 초과 조건을 추가하기 전의 결과입니다. 현재의 문턱 미달 시 롤링 처리에 대한 정확도는 별도로 평가해야 합니다.

### 종료 분류 리소스 통일

최초에는 종료 분류의 JSON 계수와 Swift 내적·softmax 구현을 `ChicEndV3_5.mlmodel`로 통일했습니다. 아래 추가 수정에서는 0.5초 입력으로 재학습한 부스팅 분류기로 같은 리소스를 교체했습니다. 특징 추출과 시간 이력 관리는 기존 코드에 남으며, 61탭 FIR은 학습 계수가 아닌 고정 전처리 상수로 보관합니다. 분류 모델은 CPU에서 실행합니다. 파일 형식 변경 자체로 정확도·속도·메모리가 개선되는 것은 아닙니다.

### 짧은 입력과 문턱 수정 (2026-11-09)

종료 모델의 현재 소리 입력을 0.975초에서 0.5초로 줄이고, 동일한 최신 125개 학습 출처 자료로 재학습했습니다. 이 종료 입력 변경 당시에는 작업 중 분류 모델 3개를 유지했고, 이후 위의 air 삼분류 변경을 적용했습니다. 종료 입력 특징은 현재 Apple 특징 512개·직전 5/15회 대비 변화 1,024개·주파수 변화 309개로 총 1,845개를 유지합니다. 0.5초는 현재 소리 특징 입력 길이이며 과거 변화 특징의 보관 기간까지 0.5초라는 뜻은 아닙니다.

최초 0.5초 전환 시 종료 분류는 깊이 3·최대 잎 7·100회 부스팅을 Core ML 트리→softmax 파이프라인으로 저장합니다. JSON 학습 가중치나 앱 내 직접 분류 계산은 없습니다. 같은 데이터에서 재학습한 약 0.139/0.245/0.459초 주파수 후보와 0.5초 선형 후보는 비교 자료에 남기고 채택하지 않았습니다.

최초 0.5초 전환 시 종료 문턱을 0.995에서 0.8로 낮추면서 실제 원음의 3dB 감소를 추가 확인합니다. 점수만 낮추는 후보의 작업 중 충돌 때문에 추가한 보조 조건이며, 기계음만 분리하거나 모든 종료음에 보편적으로 성립한다고 가정한 조건은 아닙니다. 3dB는 현재 묶음 RMS와 직전 10묶음의 평균 제곱 에너지를 비교합니다. 청소음 문턱은 0.995 1회에서 0.5 5회 연속으로 바꿉니다. 활성화 기준과 작업 점수 <0.3 20회 조건은 유지합니다.

출처 분리 개발 자료에서 종료음 경로 12/33→19/33, 청소음 경로 3/17→9/17을 확인했습니다. 새 종료음·청소음 경로의 작업 라벨 충돌은 각각 0회였지만, 기존 작업 점수 기반 소멸 경로를 포함한 전체 비교에는 8회 충돌이 남았습니다. 이 자료는 입력·문턱 선택에 재사용했으므로 새 독립 정확도나 실기기 성공률로 해석하면 안 됩니다. 이전 미학습 영상 5개 종료 참고 구간에서는 세 경로 합계가 1/5→2/5였고, 3개 구간은 여전히 놓쳤습니다. 전체 해결이나 범용 정확도를 보장하지 않습니다.

## 종료 입력 길이와 작은 음량 보정 재검증 (2026-11-09)

**현재 소리 입력은 0.5초를 유지하고 종료·청소 분류기를 200회 부스팅으로 교체했습니다. 종료 문턱은 0.85에서 0.6으로 낮췄습니다.** 종료음의 3dB 감소 조건을 제거하여 점수 0.6 이상 1회로 판단합니다. 작업 중 분류 모델과 첫 피드백 활성화, 작업 점수 <0.3 20회 연속은 유지합니다. 청소음 조건은 점수 0.7 이상 5회 연속에서 0.5 이상 3회 연속으로 완화했습니다. 절대 음량만으로 종료하지 않습니다.

일반 기기·유튜브 종료 라벨 42개의 스펙트로그램을 확인했습니다. `hmP-z_gds2s`의 약 34초 종료는 약 33.85~34.00초에 짧은 변화가 집중되지만, 다른 자료에는 약 0.6~0.75초에 걸친 방출·감쇠도 있습니다. 라벨 길이와 실제 특징음 길이는 다릅니다. 현재 추출기의 최소 입력은 0.5초이므로 0.25초 후보는 앞에 0.25초 무음을 붙여 비교했고, 0.75초는 실제 12,000샘플을 넣었습니다. 과거 변화 특징의 보관 길이는 그대로 두었습니다.

새 모델의 작업 출력을 함께 적용하면 약한 말소리 뒤 소멸 검출이 나빠졌기 때문에, 기존 100회 작업 분류기를 같은 Core ML 파이프라인 안에 보존했습니다. Apple 특징 추출은 한 번이고, 분류 리소스도 하나지만 내부 트리 계산은 기존 작업 분류 100회와 새 종료·청소 분류 200회로 늘어납니다. 추출 특징과 입력창을 공유하며 별도 Swift 가중치 파일은 없습니다.

`hmP-z_gds2s`를 영상 24초부터 앱 코드로 연속 입력했을 때, 원음과 −24dB 모두 영상 34.059초에 종료음 경로로 종료했습니다. 전체 영상 시작부터 넣으면 앞선 소리 예시 구간인 약 17.95초(감쇠본 18.06초)에서 먼저 종료하므로, 이를 전체 영상에서 34초에 첫 종료했다고 보고하지 않습니다. 해당 영상은 최종 모델 학습에 포함되어 있어 이 검사는 재현 확인이며 일반화 평가가 아닙니다.

## 시작과 종료 기준

**시작은 연습 버튼을 누른 시점이 아니라, 기존 `ChicDisplayFilter`가 첫 피드백을 확정하여 소리 확인 중 화면에서 벗어나는 시점입니다.** 그 묶음까지의 종료 점수와 낮은 작업 점수는 종료 판단에 사용하지 않습니다. 다음 묶음부터 종료 감지를 허용하며 추가 고정 대기시간은 없습니다. 작업 점수 0.5 이상 20회로 다시 활성화하는 조건과 별도의 공기주입→롤링 이력 조건은 제거했습니다.

| 우선순위 | 종료 경로 | 조건 |
|---|---|---|
| 1 | 종료음 | 종료음 점수 ≥0.6, 1회 (음량 감소 조건 없음) |
| 2 | 소멸 | 작업 점수 **<0.3, 20회 연속** |
| 3 | 청소 방출음 | 청소 점수 ≥0.5, 3회 연속 |

세 경로는 OR 조건입니다. 같은 시점에 겹치면 표의 우선순위로 한 번만 종료합니다. 종료음이나 청소음을 기다리느라 다른 경로를 지연시키지 않습니다. 작업 점수가 **정확히 0.3이거나 더 크면 소멸 횟수를 0으로 초기화**합니다. 이 조건의 소멸은 실제 기계음 분리를 뜻하지 않으며, 이전의 주파수 성분 9dB 감소 조건을 함께 요구하지 않습니다. 청소음은 점수 0.5 이상 3회 연속으로 확인하며 한 번이라도 0.5 미만이면 초기화합니다. 첫 양성부터 세 번째까지 약 0.213초이고 3묶음 분량은 약 0.320초입니다. 실제 소리 변화부터의 지연에는 모델 입력 문맥과 마이크 버퍼도 영향을 줍니다.

종료 모델은 원시 10프레임마다 약 106.667ms에 한 번 실행합니다. 20회 연속의 첫 양성부터 마지막 양성까지는 약 2.027초이며, 20묶음 길이로는 약 2.133초입니다. 입력 문맥과 마이크 버퍼 때문에 실제 소리 변화부터의 지연과는 다릅니다. 0.3 미만을 띄엄띄엄 20번 누적하지 않습니다.

| 쇳소리 `metallic` | 쇳소리 3회 연속 |
| 파바박 `sputter` | 파바박 3회 연속 |

연속 횟수는 원시 프레임이 아닌 **10프레임 집계 후 대표 판정**을 셉니다. 다른 판정이 나오면 그 판정의 1회부터 다시 세며, 공기주입과 파바박을 합산하지 않습니다. 예를 들어 `쇳소리→쇳소리→공기주입→쇳소리`는 쇳소리 3회로 인정하지 않습니다. 조건을 충족하기 전에는 직전 표시를 유지합니다. 새 연습은 소리 확인 중에서 시작하고, 초기 `other`만으로 롤링 화면을 띄우지 않습니다.

대표 판정 주기는 `10 × 512 / 48,000`, 약 106.7ms입니다. 시작부터 같은 상태를 계속 판정하는 경우 첫 공기주입 표시는 약 138.7ms, 첫 경고 표시는 약 352ms 시점에 가능합니다. 마이크 버퍼 도착·모델 문맥·오판·UI 처리로 실제 표시는 더 늦어질 수 있습니다. 별도 최소 유지시간이나 강제 전환 타임아웃은 없으므로 연속 조건을 충족하지 못하면 기존 화면을 계속 유지합니다.

필터의 묶음과 연속 횟수는 마이크 버퍼 경계를 넘어 유지됩니다. 새 연습은 새 분석기·필터를 만듭니다. 피드백 화면 전체 전환에는 애니메이션을 쓰지 않습니다. `other`에는 일반 롤링 외의 비스티밍 소리도 포함될 수 있습니다. 분석 오류는 롤링으로 숨기지 않고 연습을 종료하며 안내합니다.

## 선택 근거와 한계

아래 평가는 공기주입도 2회 연속 확인하던 시점의 결과입니다. 공기주입을 1회로 줄인 현재 규칙의 정확도와 실기기 반응 시간은 별도로 측정해야 합니다.

개발 녹음 28개에서 10~15프레임을 비교한 뒤 10프레임으로 고정하고 기존 검증 녹음 44개에서 확인했습니다. 10개와 11개의 공기주입·롤링 종합 점수 차이는 약 0.09%p였고 10개가 더 빨랐습니다. 12~15개는 전환 횟수를 더 줄였지만 일부 구간에서 연속 조건의 충족이 늦어졌습니다. 새 학습 자료와 출처가 겹치는 검증 3개는 제외했습니다.

아래 기준선은 **같은 재학습 모델에 이전 표시 규칙을 적용한 결과**이며, 예전 앱의 다른 모델 가중치와 직접 비교한 결과가 아닙니다. 정답률은 수동 라벨 구간에서 해당 화면이 표시된 시간 비율입니다.
